Core Foundations

Apa itu ETL?

ETL adalah singkatan dari Extract, Transform, dan Load — fondasi utama pemrosesan data modern.

1. EXTRACT Mengambil data mentah dari berbagai data source.
2. TRANSFORM Mengubah, membersihkan, dan menyiapkan data sesuai kebutuhan bisnis.
3. LOAD Memasukkan data yang telah matang ke target storage / Data Warehouse.

Extraction Methods

01

Full Extraction

Mengambil seluruh tabel data tanpa filter setiap kali pipeline jalan.

02

Incremental Extraction

Hanya mengambil record yang dibuat atau berubah sejak waktu extract terakhir.

WHERE updated_at > :last_extract;

Engineering Realities

Tantangan Kritis pada Tahap Extract

Hal-hal yang wajib diantisipasi oleh Data Engineer
10

Infrastruktur & Jaringan

  • Source Database Load: Query besar dapat memperlambat transaksi operasional.
  • API Rate Limiting: Batasan kuota request per menit pada sistem external.
  • Network Timeout & Retries: Jaringan terputus saat transfer jutaan baris.

Konsistensi & Schema Drift

  • Schema Changes: Kolom dihapus/ditambah di database sumber secara tiba-tiba.
  • Duplicate / Missing Data: Data hilang karena proses retry tanpa idempotency.
  • Security & Auth: Token otentikasi API yang expired di tengah proses.

High-Volume Optimization

Strategi Initial Load untuk Data Skala Besar

Mencegah memori crash saat memindahkan puluhan juta data
13

1. Full Direct Load

Menarik seluruh data dalam 1 query besar.

Cocok untuk: Data < 500K baris

2. Batch Chunks Load

Memecah query menjadi potongan berkala (misal per 100K baris / per bulan).

Mencegah query timeout

3. Parallel Partition Load

Menjalankan beberapa worker thread secara bersamaan berdasarkan ID atau partition key.

Memaksimalkan throughput

Query Strategy

Delta Load Menggunakan Timestamp

Metode filter berbasis kolom updated_at / watermark table
15
SQL QUERY PATTERN
SELECT *
FROM orders
WHERE updated_at > :last_successful_load;

Nilai :last_successful_load disimpan di metadata table sebagai checkpoint status.

1. Baca Waktu Terakhir Load
2. Filter Records di Source Database
3. Transform Changed Records
4. Upsert (Insert/Update) ke DW
Edge Cases

Tantangan Kritis pada Delta Load

Skenario khusus yang sering merusak akurasi delta load
16
CASE 01

Late-Arriving Data

Event terjadi pukul 10:00, namun baru masuk database sumber pukul 10:15 setelah pipeline selesai.

CASE 02

Hard Deletes

Jika record dihapus fisik (DELETE), tidak ada baris baru untuk ditangkap oleh timestamp query.

CASE 03

Created vs Updated

Ketiadaan kolom updated_at membuat record yang diedit tidak terdeteksi.

CASE 04

Clock Skew

Perbedaan zona waktu atau selisih detik antara server aplikasi dan database cluster.

Initial Load vs Delta Load

Perbandingan karakteristik kedua strategi pemuatan data

Karakteristik Initial Load Delta Load
Cakupan Data Seluruh data historis yang ada (All existing) Hanya data baru atau yang mengalami perubahan
Frekuensi Biasanya 1x di awal inisiasi Berkala (Hourly, Daily, atau Continuous Streaming)

Integrity Checks

4. Data Validation

Memastikan data memenuhi kriteria keabsahan sebelum dimuat ke target
22

Contoh Aturan Validasi (Validation Rules)

  • amount >= 0 (Nilai transaksi tidak boleh negatif)
  • customer_id IS NOT NULL (ID harus selalu terisi)
  • order_date <= CURRENT_DATE (Tidak ada transaksi masa depan)
  • email LIKE '%_@__%.__%' (Regex format email valid)
Data yang gagal validasi akan diarahkan ke Dead Letter Queue (DLQ) atau tabel error log untuk diinvestigasi.

Alur Delta Load Berkelanjutan

SOURCE SYSTEM
DELTA LOAD (New / Changed Data)

Prinsip Kunci:

Begitu baseline data terisi melalui Initial Load, pipeline tidak lagi membaca ulang seluruh database. Sistem berpindah sepenuhnya ke mode Delta Load berkala untuk menghemat bandwidth, biaya server, dan waktu pemrosesan.
